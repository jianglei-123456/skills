# Document structure

The skeleton below is the default. Deviate where the topic demands it — but keep the document one file and self-contained, written in the user's language.

```
# <Title>

One-sentence overview: what this document covers.

## Contents

- ... (headings of the sections below)

## 1. Core concepts

Per concept: intuition/analogy first, then definition, then an example, then the gotchas.
Repeat for each concept.

## 2. Mechanics

How things work — a process, algorithm, or pipeline — only if the topic has one.

## 3. Key comparisons

A table comparing similar concepts; what differs is the point.

## 4. Common pitfalls

The mistakes and confusions a reader would hit.

## 5. Recap

The points worth remembering, as a short list.

## 6. Sources

Every source referenced in the body, with links.
```

## Quality gates

- The overview is one sentence, not a paragraph.
- Every core concept has an analogy and an example.
- Comparisons live in tables, not prose.
- The document opens with the overview and goes straight into concepts — no motivation preamble.
